## 1. 使うもの
- **網（二つ。それぞれ別に判定する）**：EDM の公式の配布場所の
  - **VP 型**：`edm-afhqv2-64x64-uncond-vp.pkl`（`['ema']`、DDPM++）
  - **VE 型**：`edm-afhqv2-64x64-uncond-ve.pkl`（`['ema']`、NCSN++）
  - 読み込めない場合は、別の網に切り替えずに止まり、本筋に相談します。
- **サンプラー**：二つの網とも EDM の標準（決定論的 Heun、**40 歩、網 79 回**、σ 0.002〜80、ρ = 7）。範囲は `edm_sampler` と同じ決め方（sigma_min = max(0.002, 網の sigma_min)、sigma_max = min(80, 網の sigma_max)）です。範囲が 0.002〜80 でない場合や、`round_sigma` が目盛りを変える場合は、網ごとに止まります。VP 型では、範囲 0.002〜80・目盛りの変更なしを確かめ済みです。
- **s_G**：二つの網で共通です。AFHQv2 64×64 の全画像（15,803 枚。`dataset_tool.py` の出力の zip のすべて）の平均と共分散を使います。x = 画素/127.5 − 1、CHW の順、1/N で割り、float64 で計算します。d = 12,288 で固有値分解し、負の固有値は 0 にします。水増しはしません（データの二次の積率だけ）。
- **FID**：EDM と同じ Inception の重み・同じ式と、公式の `fid-refs/afhqv2-64x64.npz`。
- **乱数**：出発点は C1・C2 と同じ形です（束 b：`torch.Generator(cuda).manual_seed(1000003·種の組 + b)` の float64 の正規乱数 × σ_max、次元 12,288）。5% の点は `numpy.random.default_rng([20261112, 種の組, 歩数, b])` で、評価ごとに引き直します。**二つの規則は同じ乱数を使う**ので、切り替えるまで同じ Gall の軌跡・同じ 5% の点で同じ u を見ます（判定の違いは規則だけから出ます）。
- **枚数**：5,000 枚（1,000 枚 × 5 束）。種の組 0。FID の揺れの目安（別の種の組 1 の M0）も同じ 5,000 枚で取ります。
- **結果の置き場所**：網ごとに `C3_results/vp/` と `C3_results/ve/`。データと積率と本物の画像の FID は、`C3_results/` の直下で共通です。

## 2.4 二つの規則の定義（どちらも判定の対象）
### U_env（B22、`B22_rule_for_C.md` §3 の一般の定義のまま）
- 評価の番号 k = 0, 1, …（T1：切り替える前のすべての呼び出しを評価）、評価の雑音 σ_k（増えない列。Heun では σ_0, σ_1, σ_1, σ_2, σ_2, …）、統計量 u_k（評価した 5% の点での u_i = |D_G − D_net|²/d の中央値。網の出力が有限でない点は除き、有限な点がなければ +∞）。
  1. **窓**：W_k = { i ≤ k : ln σ_i ≤ ln σ_k + Δ }（B22 と同じく 1e-12 の余裕で含める）。3 個より少なければ、直近の 3 個に広げます（M_MIN = 3）。窓の最初の番号を a_k とします。
  2. **上の包絡**：X_i = max(u_j : j ∈ W_i)。
  3. **基準**：P_k = min(X_0, …, X_{a_k − 1})（窓より前の、過去の上の包絡の最小値）。
  4. **判定**：a_k ≥ 1 で、**min(u_j : j ∈ W_k) ≥ C × P_k** となった最初の k で、その呼び出しから全部の点を網に切り替えます（後戻りしない）。
- 定数：**Δ = 0.3、C = 1.515**（ファイルの値は 1.5150000000000001 = 1.01 × 1.5）、**M_MIN = 3**（B22 の `results/rule_constants_B22.json` のまま）。
- **歩数に合わせて定数を変えることはしません。** 定義書 §5 は EDM の 18 歩の話で、本番は 40 歩（呼び出し 79 回）なので、§3 の一般の定義をそのまま使います。
- **40 歩の時刻表での窓の大きさ**（u を使わず、評価の σ の列だけから計算したもの。全 79 評価の値は §7 の `uenv_window_sizes_40`）
  - 1 歩の Δln σ は、霧の中（σ = 80〜20）で 0.141〜0.173 です。
  - 評価 0〜8（σ = 80〜44.6）：窓は 1〜6 評価。2 歩分の Δln σ（約 0.28〜0.30）が Δ の内側に入るので、三つの σ の段にまたがります。
  - 評価 9〜54（σ = 38.3〜0.35）：窓は 3〜4 評価（今の σ の 1〜2 回と、一つ前の σ の 2 回）。2 歩分の Δln σ（0.31 以上）が Δ をわずかに越えるためです。
  - 評価 55〜78（σ ≤ 0.26）：窓は 3 評価（M_MIN）。
  - **最初に判定できる評価は 5（σ = 51.9）**です（それまでは a_k = 0）。
  - 【導出】窓の下の包絡を使うので、σ の一つの段だけで u が跳ねても（同じ σ の 2 回が両方跳ねても）、σ ≈ 38 より下では窓に一つ前の段の 2 回が入るので、それだけでは切り替わりません。σ ≈ 38 より上では、三つの段にまたがるので、なおさらです。
- 費用は T1P5 の数え方です（切り替え前の評価 1 回 0.05、切り替えた呼び出しから 1 回 1）。切り替えた呼び出しを c とすると、費用は (0.05c + 79 − c)/79 × M0 です。
- **【正直に書くこと】**
  - U_env の定数は、作った世界（設定 D）だけで決めたものです。C = 1.515 は、D では格子の端（1.01）× 1.5 で、D から強く決まった値ではありません（B22 §3）。
  - **U_env は、作った世界の標本外の W3 で外れています**：切り替えが 0.33 σ_o（帯の下の端 1/3 のすぐ外）まで遅れ、走りは 12/12 壊れました（M0 は 10/12）。原因は、σ_o のすぐ下の「短い本物の上がり」を、ちらつきと同じように見送ったことでした。
  - B22 の粗い刻み（EDM の 18 歩）での振る舞いは、B22 では試していません。40 歩も同じです。

### U_min（2.38）（B21、C2 版 2 と同じ実装）
- k ≥ 1 で u_k ≥ 2.38 × min(u_0, …, u_{k−1}) となった最初の評価で切り替えます（T1P5、切り替える前は全部の点を D_G で進める）。
- **【正直に書くこと】** U_min（2.38）は、C2 の VE（CIFAR-10）で外れています（ちらつきの跳ね 1 回で早すぎる切り替え）。B22 では、ちらつきのある条件ですべての世界で 0% でした。一方、ちらつきのない W3 では 0/12 の壊れで、短い本物の上がり（3〜5 倍）で切り替えて W3 を守りました。

### 二つの規則を並べる理由
- B22 のいちばん大事な結果は、**「ちらつきへの強さ」と「短い本物の上がりへの感度」が、一つの規則の中でぶつかる**ことでした。U_env は前者に強く後者を見送り、U_min（2.38）は後者を捉えて前者に弱い。
- 本物の二つの網で、この引き換えがどう現れるかを見るために、二つの規則を並べ、**どちらも判定の対象**にします（観察ではありません）。
- この決定は、AFHQv2 の網の u の曲線を誰も見ないうちに、本筋が行ったものです。

## 3. 予言と判定の基準（C2 と同じ形。網ごと・規則ごとに別に判定する）
「画質を落とさない」＝ FID ≤ 1.03 × FID(M0)（同じ網の、種の組 0、5,000 枚）。費用は 5 束の平均です。M0・格子・k_best は網ごとに決めます。

| 網 | 規則 | 画質と費用（FID ≤ 1.03 × FID(M0)、かつ 費用 ≤ 0.85） | 格子との比較（FID ≤ 1.03 × FID(WV_tele(k_best))、かつ 費用 ≤ 費用(k_best) + 0.10） |
|---|---|---|---|
| VP 型 | U_env | **HC9** | **HC10** |
| VE 型 | U_env | **HC11** | **HC12** |
| VP 型 | U_min 2.38 | **HC13** | **HC14** |
| VE 型 | U_min 2.38 | **HC15** | **HC16** |

- **四組の結果は並べて書き、「どれかが支持されれば良い」という読み方はしません。**
- 格子が途中で欠けている、FID がまだない、などの場合は「未判定」とします。
- VP 型の数字（確定の前に見たもの）での基準
  - 画質の基準 1.03 × 3.773 ≈ 3.886。
  - k_best = 13（σ = 9.72、FID 3.847、費用 53/79 = 0.6709）。格子との比較の費用の上限は 0.7709、FID の上限は 1.03 × 3.847 ≈ 3.962。
  - 40 歩の切り替えの呼び出しと費用の対応：呼び出し 12（σ = 32.7）0.856、13（σ = 27.8）0.844、19（σ = 16.78）0.7715、20（σ = 16.78）0.7595、23（σ = 11.72）0.723、25（σ = 9.72）0.699。
    - **費用 ≤ 0.85 には、呼び出し 13（σ ≤ 27.8）以降の切り替えが要ります。**
    - **VP 型の格子との比較（≤ 0.7709）には、呼び出し 20（σ = 16.78 の 2 回目）以降の切り替えが要ります。**

### 観察（判定に使わない）
- 別の種の M0 との FID の差（5,000 枚の揺れの目安）と、各規則の FID − FID(M0) がその揺れの中か。
- 束ごとの切り替えの σ、u の軌跡、二つの規則の切り替えの違い（同じ u の列の上で）、実時間、本物の画像 5,000 枚の FID。
- u の、霧の中のちらつき（隣り合う σ の比）と、谷の後の上がり（何倍か、何評価続くか）。B22 定義書 §8 の確かめてほしいこと 1・2 です。

## 4. 予想（計算の前。根拠に使ったものを書き添える）
根拠に使ったもの：作った世界の結果（B21・B22）、CIFAR-10 の C1・C2 の結果（どちらも見たもの）、AFHQv2 の VP 型の格子の結果（§0。本筋と実験場 C が見たもの）。AFHQv2 の u の曲線は誰も見ていないので、下の予想は、CIFAR-10 の網と同じ作りの網なら同じ形だろう、という見立てに頼っています。

- **【数値・事後の当て直し、CIFAR-10】** C2 の記録（切り替えまでの Gall の軌跡と u の列）に U_env を当てると、次のとおりでした。
  - VP（CIFAR-10）：σ = 12.91 が 6 束、8.40 が 4 束、費用 0.731（U_min 2.38 の 0.772 より半歩ほど遅い。格子の最良 8.40 以上で、最良 + 0.10 = 0.757 の内側）。
  - VE（CIFAR-10）：σ = 5.32 が 8 束、8.40 が 2 束、費用 0.653。σ = 40.79 の跳ねは見送りましたが、格子の最良（σ = 8.40）より下まで遅れました（C2 で σ = 5.32 の WV_tele は FID が基準をわずかに越えていました）。
- **VP 型（AFHQv2、DDPM++）**
  - 【予想】CIFAR-10 の VP と同じく、霧の中の u は滑らか（ちらつきが小さい）と見ます。
  - **U_min（2.38）**：σ ≈ 12〜20（呼び出し 17〜24）で切り替わり、費用 0.72〜0.80。切り替えは k_best の σ（9.72）より上なので FID は落ちない。→ **HC13 支持**。HC14 は、呼び出し 20 以降で切り替わる束が多ければ通り、σ = 19.95 以上で切り替わる束が混じれば越えます。→ **HC14 は境目で、どちらとも言えない**。
  - **U_env**：U_min より 1〜2 評価遅く、σ ≈ 9.7〜14（呼び出し 21〜26）で切り替わり、費用 0.69〜0.75。→ **HC9 支持寄り、HC10 支持寄り**。σ = 9.72 より下（呼び出し 27 以降）まで遅れると、格子が通らなかった σ（k = 16、σ = 5.38）に近づき、FID の側で境目になります。
- **VE 型（AFHQv2、NCSN++）**
  - 【予想・確かめていない見立て】CIFAR-10 の VE の網と同じく、ノイズの大きさを振動する Fourier 特徴で渡す作りなので、霧の中にちらつきが出ると見ます（C3 §1.4 の見立て）。
  - **U_min（2.38）**：霧の中の跳ねで早すぎる切り替え（σ ≥ 30、呼び出し 12 以前）をする見込みが高く、費用は 0.85 を越える。→ **HC15 不支持寄り、HC16 不支持寄り**（費用の側）。FID は落ちない見込みです。ただし、40 歩の目盛りが跳ねに当たらなければ、VP 型と同じ振る舞いになります。
  - **U_env**：跳ねは見送る見込みです（σ ≈ 38 より下では、窓に一つ前の段が入るため）。ただし CIFAR-10 の VE のように、跳ねの後の静かな底が低く出ると、遅れて k_best の σ より下で切り替わり、FID の側で境目になる見込みです。40 歩は 18 歩より刻みが細かいので、遅れは σ で見て CIFAR-10 より小さいと見ます。→ **HC11 は分からない（FID の側で境目）、HC12 は分からない**。
- まとめの見込み：VP 型では二つの規則とも通りやすく、U_min が早め・U_env が遅め。VE 型では「U_min が早すぎ、U_env は遅めだが通るかもしれない」という、B22 の引き換えの片側（ちらつき）が現れると見ます。

## 5. 外れたときの読み方（先に書いておく）
### B22 の引き換えに当たる場合
- **U_env が遅すぎて画質を落とし、U_min は通る**（HC9 または HC11 が FID の側で不支持、同じ網の HC13 または HC15 が支持）
  - 本物の網にも「短い本物の上がり」があり、持続を求める U_env がそれを見送った、と読みます（B22 の W3 と同じ形）。同じ u の列の上で、U_min が切り替えた所と U_env が切り替えた所を並べ、上がりが何評価続いたか、その後に二つ目の谷があったかを確かめます。
- **U_min が早すぎて節約が足りず、U_env は通る**（HC13 または HC15 が費用の側で不支持、同じ網の HC9 または HC11 が支持）
  - 本物の網のちらつきに U_min が反応し、U_env はそれに耐えた、と読みます（C2 の VE と同じ形）。U_min が切り替えた評価の u が、それまでの最小値の何倍か、同じ σ の 2 回がそろって跳ねたかを確かめます。
- **同じ網で両方とも外れる**
  - U_min が早すぎ（費用）、U_env が遅すぎ（画質）なら、ちらつきと短い本物の上がりの両方がある網で、この定数ではよい中間がない、と読みます。B22 の引き換えが本物の網で両側から出た、という結果です。
  - 両方とも早すぎる（費用）なら、霧の中の u が、ちらつきではなく持続して上がっている（霧が晴れる前の本物の上がり）と読みます。両方とも遅すぎるなら、霧が晴れた後の上がりが緩く、どちらの倍率にも届くのが遅い、と読みます。
- **同じ網で両方とも通る**
  - その網では引き換えがぶつからなかった、と書きます。費用と切り替えの位置の差を並べます。
- **網によって違う**（たとえば VP 型では両方通り、VE 型では U_min だけ外れる）
  - 網の作り（DDPM++ と NCSN++）による違いとして書きます。どちらかの網の結果で、もう一方の網の結果を打ち消すことはしません。

### そのほか
- **合図が立たない**（最後まで切り替えない）：FID は大きく悪くなります。前提（霧が晴れると u が上がる）が、その網で成り立たなかったと読みます。
- **格子の最良に届かないだけ**（画質と費用は支持、格子との比較は不支持）：答えを見て選ぶ格子に、答えを見ない規則が、費用か画質のどちらで届かなかったかを分けて書きます。VP 型では、呼び出し 19 と 20 で費用の上限をまたぐ（0.7715 と 0.7595）ので、半歩の差で決まり得ることを先に書いておきます。
- **FID の差が、別の種の M0 との差より小さい**：判定は基準どおり書き、その差は 5,000 枚の揺れの中にあると注記します（VP 型では、別の種の M0 との差が 0.072 で、画質の基準の幅 0.113 と同じ桁です）。
- **画像の枚数が 15,803 枚でない、目盛りが登録と違う、網が読み込めない**：ノートブックが止まります。本筋に相談し、登録を変える必要があれば版を上げて登録し直します。
- この網での結果は一度だけの試験です。外れても、この網を見て規則や定数を決め直すことはしません（決め直すなら作った世界で）。

## 6. 正直に書くこと
- U_env の定数（Δ = 0.3、C = 1.515、M_MIN = 3）は、作った世界（設定 D）だけで決めたものです。C = 1.515 は、D では格子の端 × 1.5 で、強く決まった値ではありません。
- **U_env は、作った世界の標本外の W3 で外れています（遅すぎ、12/12 壊れ）。** U_min（2.38）は、C2 の VE（CIFAR-10）で外れています（早すぎ）。
- 倍率 2.38 は、作った四つの世界を見て決めた値です。
- 本筋と実験場 C は、確定の前に、AFHQv2 の VP 型の規則に関わらない部分（M0・格子・別の種の M0 の FID と費用）を見ました。u の曲線と切り替えの σ は、どちらの網でも見ていません。
- s_G は、データの平均と共分散（二次の積率）だけを使います。
- 他者のコードと重み（EDM の VP 型・VE 型の網、Inception）とデータ（AFHQv2、CC BY-NC 4.0）は、私たちのフォルダに入れず、公式の場所から読み込みます。
